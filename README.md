# MLChat для ГИС-помощника

Устанавливаемый Python-модуль: русский запрос → интерпретация или уточнение →
проверенный `FilterV1` существующего backend.

Подключение: `DIALOGUE_FACTORY=mlchat.integration:create_dialogue`.
HTTP API, сессии, авторизация, LLM-транспорт, исполнение GIS-запросов и карта
принадлежат backend/frontend.

## Состав репозитория для подключения

| Путь | Назначение |
| --- | --- |
| `mlchat/` | Интерпретатор, промпт, состояние уточнений, проверки и фабрика |
| `mlchat/backend-reference.json` | Версия и контрольные суммы совместимого backend |
| `pyproject.toml` | Зависимости и сборка пакета для Python 3.12 |
| [docs/mlchat.md](docs/mlchat.md) | Установка, настройки, рабочий контракт и ограничения |
| [Modelfile.qwen14b](config/ollama/Modelfile.qwen14b) | Проверенный профиль уже скачанной Qwen2.5 14B |
| [Modelfile.qwen35-9b](config/ollama/Modelfile.qwen35-9b) | Qwen3.5 9B: контекст 8192, ответ до 512 токенов; применяется с отдельной фабрикой |
| `scripts/build_mlchat_backend_reference.py` | Сборка совместимого wheel из исходного ZIP, если владелец backend не предоставил артефакт |

Wheel содержит только пакет `mlchat` и служебные метаданные. В исходный архив
дополнительно входят инструкция, профиль модели и сборщик эталонного backend.

## Сборка и передача

Получить и установить `gis-assistant-backend==0.1.0`, совместимый с
`mlchat/backend-reference.json`. Затем из корня репозитория:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install 'build>=1.2,<2' 'hatchling>=1.27,<2'
.\.venv\Scripts\python.exe -m build --wheel --no-isolation
```

Владельцу backend передать `dist/gis_assistant_mlchat-0.1.3-py3-none-any.whl`
и [инструкцию подключения](docs/mlchat.md). Готовые сборки не хранятся в Git.

## Модель и текущий статус

В версии 0.1.3 уточнены правила выбора между фильтром, вопросом и отказом.
Профиль `mlchat-qwen35-9b` прошёл исходные **32/32 сценария в трёх прогонах**:
медиана шага 1,891 с, максимум 5,640 с. До изменения промпта с тем же
профилем и исправленным сравнением диапазонов было 29/32.
Методика, отдельная проверка новых формулировок и ограничения —
в [протоколе качества](docs/mlchat-quality.md).
На новых формулировках — **27/32**: свободный ввод пока не прошёл приёмку.
Среди оставшихся ошибок есть подмена OR на AND; готовность к MVP не заявляется.

Предыдущие сравнения моделей, включая 31/32 у Qwen2.5 14B, сохранены
в [историческом протоколе](docs/mlchat-qwen35-9b.md).
Другие модели с новым промптом повторно не измерялись.
Результаты интерпретации не подтверждают сквозной MVP с GIS-бэкендом.

Для настройки 9B в версии 0.1.2 добавлен отдельный профиль. На машине с Ollama:

```powershell
ollama create mlchat-qwen35-9b -f config/ollama/Modelfile.qwen35-9b
$env:LLM_MODEL = 'mlchat-qwen35-9b'
$env:DIALOGUE_FACTORY = 'mlchat.integration:create_qwen35_9b_dialogue'
$env:LLM_BASE_URL = 'http://localhost:11434'
$env:LLM_RESPONSE_MODE = 'json_schema'
```

Фабрика явно передаёт отключение рассуждений, температуру 0 и top_p=0.8 через
штатный LLMClient backend. Modelfile задаёт контекст 8192, ответ до 512 токенов
и отключает штрафы повторения. В серверном окружении сначала установить новый
wheel, затем применить настройки и перезапустить backend. Одной смены LLM_MODEL
недостаточно. Подробности — в [инструкции подключения](docs/mlchat.md#профиль-qwen35-9b).

API получил нужные параметры и вернул ответ без рассуждений.
Полное прохождение исходного набора не гарантирует правильность любой фразы.

## Локальные материалы

В `.gitignore` исключены тесты, эталоны, ручной REPL, инструмент сравнения моделей
и его отчёты, прежний расширенный AST и проверочные геоданные. Они сохранены на
диске, но не входят в новый клон и поставку модуля. Окружение, кэши, сборки,
веса моделей, локальная база знаний и секреты также исключены.

Это состав поставки для подключения, а не замена проверки качества.
Если тестировщику нужны существующие сценарии и геоданные, их необходимо передать
отдельно: из нового клона этих материалов получить нельзя.
